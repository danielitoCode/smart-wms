## 1. Contrato y alcance

**Snapshot de implementación inspeccionado:** `d0f72975bb54452ed3b1758e23e92c61c8460faf`. La consulta de estado combinado no devolvió checks y el endpoint de runs asociados consultado no devolvió ejecuciones PR; por tanto, no hay evidencia CI disponible para declarar verde este snapshot.

F1.2 centraliza el comportamiento transversal de navegación sin mover reglas de negocio desde sus features ni duplicar la policy de permisos.

- Una URL legacy o no canónica revisada redirige a una única ruta canónica.
- Las redirecciones ocurren en `src/hooks.server.ts`, antes del matching de rutas. Esto cubre accesos directos incluso si la ruta legacy deja de tener una página Svelte asociada.
- Se conserva query string; el helper conserva también el fragmento cuando el navegador lo incluye en la URL.
- La sesión anónima conserva `pathname + search` al redirigir a login.
- Después de autenticarse, el usuario vuelve al deep link interno solicitado; una URL externa, protocol-relative, con backslash o que recursivamente apunta a login se descarta.
- Si la sesión requiere cambio obligatorio de contraseña, `/change-password` prevalece sobre el deep link.
- Los guards de página siguen usando `routeAccessPolicyForPath` y `AccessPolicy`; una ruta sin policy explícita falla cerrada. El layout muestra estado forbidden y no renderiza el contenido protegido.
- La autorización real continúa siendo responsabilidad de Flask. El guard Svelte es UX y no sustituye respuestas 401/403 del servidor.

## 3. Guardas y retorno de navegación

- El grupo `(app)` aplica el redirect de aliases antes de renderizar páginas.
- El shell autenticado consulta la policy central; `null` significa ruta no revisada y acceso denegado.
- El guard conserva la URL protegida al enviar un usuario anónimo a `/login?redirect=...`.
- `LoginScreen` usa el mismo sanitizador tanto al completar login como al detectar una sesión ya activa.
- El cambio obligatorio de contraseña prevalece sobre cualquier destino recibido.
- El logout sigue limpiando el snapshot local y vuelve a `/login`.
- Se actualizan enlaces internos para evitar que el propio menú siga generando URLs legacy.

## 7. Correcciones tras la primera validación local

El usuario reportó `svelte-check` con error de resolución para `$lib/navigation/routeAliases`. El `tsconfig.json` del proyecto define aliases `#lib/*`, `#core/*` y `#shared/*`, pero no `$lib/*`; se sustituyó el import por `#lib/navigation/routeAliases`, que corresponde al alias configurado.

El Smoke Test recibió 404 en `/api-tokens`. Para evitar depender de que la URL legacy tenga un route node coincidente dentro de `(app)`, la resolución se movió a `src/hooks.server.ts`, antes del matching de rutas. Se eliminó el `src/routes/(app)/+layout.ts` redundante. Debe repetirse Playwright con el servidor web reiniciado desde el código actualizado para confirmar status 308 en todas las rutas.
