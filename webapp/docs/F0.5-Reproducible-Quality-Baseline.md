## 1. Criterio de F0.5

El cierre requiere una ejecución reproducible y asociada a un SHA, con resultados explícitos para:

1. instalación reproducible desde lockfile;
2. `npm run check` (SvelteKit sync + svelte-check + TypeScript);
3. `npm run build`;
4. Vitest por dominio, aplicación, infraestructura, UI/i18n, integración y suite completa;
5. smoke/browser E2E con el entorno aislado documentado;
6. CI remoto y clasificación de fallos preexistentes frente a regresiones;
7. comandos, versiones, logs/resultados y limitaciones reproducibles.

Un job abortado en typecheck no acredita build ni tests posteriores. Un workflow backend `Tests` no sustituye la suite Svelte/Vitest ni Playwright.

Confirmar primero el contenido actual de `scripts/r2-e2e/config.json` y que los puertos no estén ocupados. No ejecutar pruebas mutativas contra datos reales.

Guardar salida completa y exit code de cada comando. Si `npm run check` falla, ejecutar build y suites por separado solo para diagnóstico y etiquetar que el pipeline CI normal las habría omitido; no cambiar el orden de gates ni ocultar el fallo.
